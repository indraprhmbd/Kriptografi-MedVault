# 002 - Phase 1: Multi-Factor Auth, USB Dongle, Windows Hello, and Webcam

## 1. Overview of the 3-Factor Cloud-Ready MFA Gate

Because the Go backend runs on a remote VPS accessed via HTTPS, hardware verification is performed through modern browser APIs paired with cryptographic verification on the server:
1. **Factor 1 (Knowledge - Password):** Verified on the server using **Argon2id** (`m=16384` KiB, `t=2`, `p=2`, salt=16B, keyLen=32B) so RAM usage during login never spikes above 16 MB on the VPS.
2. **Factor 2 (Possession - Physical USB Dongle `.medkey`):** Verified using the Browser **File System Access API (`window.showDirectoryPicker`)** + **Ed25519 Challenge-Response** + **2-Second USB Unplug Heartbeat**.
3. **Factor 3 (Inherence - Biometric Gate):** Supports **Windows Hello (`navigator.credentials` WebAuthn)** AND **Live Webcam Snapshot (`getUserMedia`)** matched via **64-bit Difference Hash (dHash)** in pure Go.

## 2. Factor 2: Physical USB Dongle Architecture (`web/js/usb_dongle.js` & `internal/crypto/ed25519.go`)

### 2.1 Structure of the `.medkey` File on the USB Flash Drive
Generated by `go run ./cmd/medkeygen -out /path/to/usb/.medkey -user dr_andi`:
```json
{
  "version": 1,
  "key_id": "DONGLE-2026-DR-ANDI-01",
  "username": "dr_andi",
  "algorithm": "Ed25519",
  "public_key_hex": "a1b2c3...",
  "private_key_seed_hex": "9f8e7d...",
  "issued_at": "2026-11-12T10:00:00Z"
}
```

### 2.2 Browser USB Connection and Continuous Presence Polling
1. On the Login screen, the doctor clicks **"Hubungkan Port USB Dongle"**.
2. JavaScript calls `const dirHandle = await window.showDirectoryPicker({ mode: 'read' })` where the doctor selects the mounted USB flash drive root directory.
3. JavaScript looks up `await dirHandle.getFileHandle('.medkey')`, reads and parses the JSON in memory, and displays `Status Dongle: TERHUBUNG (DONGLE-2026-DR-ANDI-01)`.
4. **Continuous Physical Unplug Detection:**
   * A background timer runs every `2000ms` calling `dirHandle.getFileHandle('.medkey')` and reading the file metadata.
   * The instant the physical USB flash drive is pulled from the laptop USB port, the browser throws `NotFoundError` or `NotReadableError`.
   * Alpine.js immediately triggers `lockSession("USB Dongle dicabut! Akses terkunci otomatis.")`, clears decrypted data from the DOM, and calls `POST /api/v1/auth/logout`.
   * *Fallback Compatibility:* If a teammate tests on a browser without `showDirectoryPicker` (such as Firefox), provide a fallback `<input type="file" accept=".medkey">` with a visible badge indicating `Mode Kompatibilitas File`.

### 2.3 Cryptographic Challenge-Response
1. Browser requests `GET /api/v1/auth/challenge?username=dr_andi` -> Server returns a random 32-byte `challenge_hex` valid for 60 seconds.
2. Browser signs `challenge_hex` using the Ed25519 private key from `.medkey` (via WebCrypto Ed25519 or embedded lightweight `tweetnacl-js` / `noble-ed25519` helper).
3. Server verifies `ed25519.Verify(user.PubKey, challengeBytes, sigBytes)`.

## 3. Factor 3: Windows Hello (WebAuthn) + Webcam 64-Bit dHash (`internal/biometric/`)

### 3.1 Windows Hello Passkey (`internal/biometric/webauthn.go`)
* During user registration, the user can click **"Daftarkan Windows Hello (PIN / Sidik Jari / Wajah OS)"** which invokes `navigator.credentials.create({ publicKey: ... })` with `authenticatorAttachment: "platform"` and `userVerification: "required"`.
* During login, clicking **"Verifikasi via Windows Hello"** invokes `navigator.credentials.get({ publicKey: ... })`, triggering the native Windows Security prompt.

### 3.2 Pure-Go Webcam 64-Bit Perceptual dHash (`internal/biometric/dhash.go`)
To avoid heavy C++ OpenCV dependencies while still verifying live webcam presence:
1. Browser captures a centered square face crop (`256x256` PNG) from `<video>` using an overlay guide box on the login screen.
2. Go decodes the PNG via standard library `image/png`:
   * Convert the face region to grayscale luminance (`Y = 0.299R + 0.587G + 0.114B`).
   * Downsample the grayscale image to a `9x8` grid (9 columns, 8 rows) using bilinear/box averaging.
   * For each of the 8 rows and first 8 columns, set bit `1` if `pixel[row][col] > pixel[row][col+1]`, else `0`.
   * Pack the 64 bits into a `uint64` (`16-char hex string`).
3. **Similarity Matching:**
   * Compute the **Hamming Distance** between `enrolled_dhash` and `live_dhash` using `bits.OnesCount64(enrolled ^ live)`.
   * Convert to similarity percentage: `similarity = (64.0 - float64(distance)) / 64.0 * 100.0`.
   * If `distance <= MEDVAULT_DHASH_MAX_DISTANCE` (default `14`, i.e., `>= 78.1%` structural similarity), biometric check passes.
